## 질문에 대한 답

[CHAT-RECOVERY.md](../2026-10-07-block-hierarchy-implementation/CHAT-RECOVERY.md)에 기록된 숨김·격리, 코드/그래프 부모와 중첩 호출, 긴 코드 편집, 원문 가져오기와 실제 선언 분석은 이미 코드에 구현되어 있었다. 그 문서는 계획이 아니라 이전 구현과 대화의 복원 기록이다. 역사적 32 PASS·5 DEFERRED와 211 JS·166 Python 결과를 이번 재검사의 숫자로 사용하지 않는다.

이번에는 **현재 Lean 파일의 정리 하나를 편집 가능한 GLEAN 그래프로 변환**하는 기능을 추가했다. 정리 입력을 입력 노드와 실제 와이어로 연결하고, 큰 증명을 호출하는 LeanScript 블록을 만든다. 호출 본문·포트·연결을 편집하고 기존 전체 Lean 검사로 다시 검증할 수 있다.

## 사용 방법과 경계

1. `.lean`을 열거나 π 무리성 예제를 선택한다.
2. **선언 / 의존 분석**을 실행하고 정리 카드를 펼친다.
3. **이 선언을 GLEAN 그래프로 변환**을 누른다.
4. **Lean으로 검증**을 실행한다. 변환 직후는 미검증이다.
5. 그래프 속성의 **보존된 Lean 원문 보기**, **원문 문서로 돌아가기**, **원문 모듈 저장**을 사용한다. 변환·원문 복귀는 Undo/Redo에 포함되고 복귀를 취소하면 편집 중이던 그래프로 돌아온다.

지원 대상은 공개·안전한 단형 정리이며 입력은 최대 16개다. namespace·section·지역 notation, 공개 타입 별명, 의존·암묵·instance 입력, 증명 본문에서 사용하는 private 보조정리를 보존한다. 그래프의 입력 계약과 호출은 명시적인 인자이다. 블록에서 새 코드를 쓸 때 원문의 instance 검색 문맥이 자동 복원된다고 주장하지 않는다.

private 정리, universe 다형 선언, 시그니처에 private 타입·정의를 직접 사용하는 공개 정리, 오류가 있는 파일은 구체적인 이유를 표시하고 원문을 유지한다. 과거 분석 캐시와 다른 소스·환경의 응답으로 변환을 허용하지 않는다.

이 기능은 **원문 보존형 선언 호출 그래프**이다. `have/calc/cases` 본문 전체를 작은 전술 블록으로 자동 분해하지 않는다. P2의 독립 정의 복제·의존 문맥 추출·원자적 치환·데이터 의미 보존과 P3의 전술 자동 그래프화는 여전히 후속 작업이다.

## 구현과 검증 근거

`graph.sourceContext`에 원문 전체, 원문·환경 hash, 선언 출처와 최초 파일 바이트를 보관한다. 서버가 실제 현재 파일 분석 작업을 확인한 뒤 고정 `GleanUploadedSource` 모듈을 생성한다. 원문을 잘라 붙이거나 설치 환경의 같은 이름 선언으로 바꿔 호출하지 않는다.

원문 모듈, 생성 그래프, 독립 목표 시그니처를 각각 빌드한다. 원문과 그래프의 선언을 커널로 replay하고 독립 목표 타입을 대조한다. 그 뒤 공리 정책을 적용한다. 원문의 `sorry`를 호출하면 미완성이며 사용자 공리는 거부된다. 커널 통과와 정책 승인·완성도를 구별한다.

감사에서 발견한 타입 별명 조회와 암묵 instance 인자 소실을 고쳤다. 재파싱용 타입은 원문의 pretty-printer 옵션과 독립적으로 완전한 인자를 출력하고 사람용 간결한 표현을 별도로 유지한다. 이미 커널이 승인한 선언만 Meta 관찰 환경에 등록하며, 이 등록은 커널 승인·목표 대조·공리 검사를 대체하지 않는다.

- 독립 실제 Lean 실험: **16/16 PASS**. [fixture](acceptance_experiment.py), [결과 JSON](acceptance-results.json).
- 설계 감사: **10/10 기대 동작 통과**, 별도 재귀 귀납 타입 보충 1건도 커널 통과. [재현 코드와 경계](DESIGN-AUDIT.md).
- 최종 JavaScript 전체 회귀: **220/220**, 실패·건너뜀 0. [로그](final-js.log).
- 240초 예산 적용 후 Python 전체 통합: **174/174**, 실패·건너뜀 0, 526.973초. [로그](final-python-integration.log). 이 실행 도중 추가 발견한 취소 경쟁 수리는 별도 관련 검사 **16/16**과 독립 프로세스·HTTP 감사 **14/14**로 재검사했다. [관련 로그](final-cancel-budget-controlled-tests.log), [수락 결과](budget-acceptance-results.json). 이후 360초 조정은 관련 7개·독립 감사 14개와 실제 브라우저 π 검사로 확인했으며 전체 Python을 360초 기준에서 다시 실행한 것으로 보고하지 않는다.
- Lean 빌드 4 jobs와 `tests/Smoke.lean`, `git diff --check`, 새 제품·테스트 파일의 trailing-whitespace 검사 통과.

원문 보존 그래프의 검사는 서버가 정한 **총 360초** 예산을 사용한다. 일반 소스·그래프는 기존 **총 120초**다. 작업 시작 이후 원문 빌드·생성 그래프 빌드·독립 목표 빌드·커널 감사에 하나의 제한을 적용하고 단계·경과 시간을 표시한다. 클라이언트의 timeout 필드로 늘릴 수 없다. 취소 경쟁에서 같은 child를 중복 종료하던 문제와 예외 시 포인터 정리 누락을 고쳤다. 이미 종료된 child의 권한 오류만 무해 처리하고 살아 있는 child의 오류는 숨기지 않는다.

## 내보내기와 목표 조회

그래프 JSON에는 보존 원문도 포함된다. Lean 내보내기는 생성 파일과 `GleanUploadedSource.lean`을 함께 저장하며 원문 모듈의 개별 저장 버튼도 제공한다. 두 파일을 같은 Lake 프로젝트에 보관한 뒤 다음과 같이 확인한다. 프로젝트의 `.lake/build/lib/lean` 경로는 기존 빌드에서 준비되어 있어야 한다.

```sh
lake env lean -o .lake/build/lib/lean/GleanUploadedSource.olean GleanUploadedSource.lean
lake env lean GeneratedGraph.lean
```

보존 원문을 사용하는 그래프의 커서 목표 조회는 아직 지원하지 않는다. **원문 문서로 돌아가기** 후 실제 Lean 목표를 조회하거나 전체 그래프 검사를 실행한다. 일반 그래프와 원본 Lean 문서의 기존 LSP 목표 조회는 유지된다.

## 브라우저 관찰

실제 π 파일의 49개 선언에서 `irrational_pi`를 선택해 그래프로 변환했다. 변환 Undo → 원문, Redo → 그래프, 새로고침 자동 복구 → 미검증 그래프, 원문 문서 복귀 → Undo로 그래프 복원을 확인했다. 실제 변환 API가 반환한 [π 그래프 JSON](pi-converted.glean.json)을 브라우저 파일 선택기로 다시 열었고, 저장된 검증을 신뢰하지 않고 미검증으로 표시하는 것을 확인했다. 원문 복귀 시 14,049바이트와 SHA-256 `0c041eca65dd0f02330634e15db157fb07e79db045b078c8cc3bfd7b14c321cf`를 확인했다. 745×625 화면에서 패널 탭과 코드 편집·원문 도구에 접근했다. 보존 원문 제목·ARIA와 생성 그래프/원문 모듈의 두 파일 내보내기 라벨·도움말도 대조했다. 화면 검사 도구의 과거 DOM snapshot을 실제 AX·스크린샷으로 대조해 탭·판정 표시 자체의 오류로 잘못 계산하지 않았다.

최초 π 그래프 검사와 단독 재검사 모두 120초 제한으로 끝났고 검증 완료로 표시되지 않았다. 단독 실행은 분석 36.4초, 원문 빌드 12.6초, 그래프·독립 목표 빌드 약 68.5초를 쓴 뒤 커널 감사 단계에서 시간 제한에 도달했다. [수리 전 로그](pi-experiment-120s.log), [판정 JSON](pi-results-120s.json)을 보존했다.

수리 후 다른 Lean 작업 없이 [실제 π 실험](pi_experiment.py)을 재실행했다. 분석은 46.2초에 완료됐으며 다음 두 대조가 통과했다. [실행 로그](pi-experiment.log), [실제 결과 JSON](pi-results.json).

| 호출 블록 | 실제 결과 | 검사 시간 |
|---|---|---|
| `@irrational_pi` | `valid`, `verified=true`, `sourceContextKernelAccepted=true`, 표준 Lean 공리 정책 통과 | 170.568초 |
| `by exact True.intro` | `invalid`, `verified=false`; `True`/`Irrational Real.pi` 실제 타입 불일치; `root/source_call` 본문 1행 4열 대응 | 134.526초 |

각 검사는 총 240초 제한을 사용했다. 오류 대조는 그래프 컴파일 단계에서 거부되어 원문·그래프 커널 감사 통과를 주장하지 않는다. 정상 대조는 원문·그래프·독립 목표를 모두 커널 검사한 결과이다. 이 시간은 이번 로컬 실행의 관찰이며 모든 mathlib 파일의 완료 시간이나 변환 가능성을 보장하지 않는다.

같은 π 변환 파일을 브라우저에서 재검사했을 때는 독립 커널 감사 단계에서 총 240초를 초과했다. [실패 화면](ui-timeout-240s.jpg), [실제 AX 기록](ui-timeout-240s.txt)을 보존했다. CLI 통과를 브라우저 통과로 대신 기록하지 않는다. 이 실행 시간 편차를 반영해 원문 포함 그래프의 기본·상한을 360초로 조정했고 일반 120초와 모든 검증 단계를 유지했다. 수정 후 예산·취소 Python **7/7**, 진행 표시 JS **6/6**을 재검사했다. [Python 로그](budget-360-final-python-tests.log), [JS 로그](budget-360-final-js-tests.log).

360초 경계에 대한 별도 프로세스·HTTP 수락 감사도 **14/14** 통과했다. 경과 240.5초의 원문 포함 작업은 계속 실행하고 360.5초에서는 시간 제한에 도달하며, 일반 POST는 기존 120초를 유지한다. [360초 수락 결과](budget-acceptance-360s-results.json), [감사 부록](ACCEPTANCE-AUDIT.md). 재검사 중 서버가 실제 사용한 생성 코드와 보존 원문도 CLI 결과와 동일한지 비교했다. [코드 hash 대조](native-code-comparison.json).

최신 서버에서 π 변환 파일을 다시 검사했고, 화면에 총 제한 360초와 실제 컴파일·커널 감사 단계를 확인했다. 검사 완료 후 **현재 목표 · 커널 검증 완료**와 표준 공리 `Classical.choice`, `Quot.sound`, `propext`가 표시됐다. 전체 맞춤 이후에도 성공 표시가 유지됐다. [최종 실제 화면](ui-final-verified.jpg), [완료 AX 기록](ui-final-verified.txt). 화면에서 정확한 최종 소요 시간을 노출하지 않으므로 CLI 대조의 170.568초를 이 브라우저 실행 시간으로 사용하지 않는다. 실제 π 검사는 수분이 걸렸으며 변환 파일을 다시 열었을 때의 미검증 상태와 구별한다.

IAB에서 파일 저장 버튼을 눌렀지만 download 이벤트와 실제 저장 파일을 확인하지 못했다. 다운로드 링크를 DOM에 붙여 클릭하는 호환성 보완과 관련 회귀는 통과했으나, IAB의 실제 파일 저장 완료를 검증했다고 주장하지 않는다. JSON 저장·재열기 모델 검사와 브라우저 자동 복구는 이 관찰 제한과 구별한다.
