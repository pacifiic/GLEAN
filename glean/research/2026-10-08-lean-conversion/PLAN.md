## 첫 변환의 범위

실제 Lean에서 분석한 업로드 파일의 공개·단형 정리 하나를 선택하여 v3 편집 그래프를 만든다. 입력 telescope를 입력 노드와 포트로 만들고, 선택한 정리를 호출하는 편집 가능한 LeanScript 노드에 실제 와이어로 연결한다. 반환 포트를 그래프 결과로 설정한다.

이 기능의 이름은 **선언 호출 그래프 변환**이다. 정리의 `have/calc/cases` 본문 전체를 작은 증명 블록으로 자동 분해하는 기능은 아니다. 선언의 상수 참조 관계를 증명 포트 와이어로 바꾸지 않는다. 설치 환경의 같은 이름 선언으로 바꿔 호출하지 않는다.

## 원문과 문맥

전체 파일을 `graph.sourceContext`에 보존하고 고정 모듈 `GleanUploadedSource`로 빌드한다. namespace, section, notation, instance, private 보조정리가 있는 원문을 조각내거나 생성 코드 앞에 붙여 재해석하지 않는다. 생성 그래프와 독립 목표 시그니처는 같은 원문 모듈을 사용한다. 원문 모듈도 별도로 커널 replay해야 한다.

변환용 metadata는 서버의 실제 분석 작업과 소스 hash·프로젝트·환경이 일치해야 한다. 저장된 과거 캐시만으로 변환을 승인하지 않는다. 타입 표시를 호출 코드에 사용할 때는 완전한 이름과 notation을 해제한 표현 등 재파싱 가능한 형태를 얻는다.

전체 파일 오류, private 대상, 미확정 universe, 비명제 반환 대상, 지원하지 않는 이름·입력 크기·기타 표현은 원본문서를 유지하고 이유를 표시한다. 변환 직후는 미검증이다. 기존 목표·커널·공리 정책을 완화하지 않는다.

## 감사와 검증

에이전트 1은 제품 변경과 테스트를 구현하고, 에이전트 2는 요구사항을 독립 대조하며, 에이전트 3은 설계·출처·커널·비동기 오류를 감사한다. root는 실제 브라우저 동작과 최종 빌드·회귀를 확인한다. 발견 사항은 구현자가 수정하고 같은 입력으로 재시험한다.

핵심 양성 대조는 지역 보조정리를 사용하는 namespace/section 정리, `n : Nat`과 `i : Fin n` 의존 입력, 실제 π 원문이다. 음성 대조는 잘못된 본문, `sorry`, 추가 공리, 선언 타입 변경, private/universe/부분 오류, 오래된 소스와 환경이다. 실제 Lean 실행, 순수 모델, controlled UI transport, native UI 관찰을 구별해서 결과를 기록한다.

완료 상태와 실행 결과는 같은 폴더의 README.md에 기록한다. 구현 전 계획은 검사 성공을 주장하지 않는다.
