# Grasshopper 기능 구현 수락 기준

Copyright (c) 2026 GLEAN contributors. Released under Apache 2.0.

이 문서는 사용자가 구현을 요청한 직전 답변의 **15개 기능 전체**를 요구사항으로 고정한다.
Agent 1은 구현, Agent 2는 이 문서의 요구사항 검증, Agent 3은 설계·코드 검토를 맡는다.
쉬운 UI 기능만 남기거나 실제 Lean 기능을 예제 문자열·모형 데이터로 대체하지 않는다.
제품 코드의 소유자는 구현 담당자이며, 이 문서는 요구사항 감사 기록이다.

## 판정 규칙

- **PASS:** 사용자에게 접근 가능한 기능, 실제 데이터 경로, 해당 양성·음성 대조, 필요한 저장·복구 증거가 모두 확인됨.
- **PARTIAL:** 일부 실동작은 확인됐으나 요구된 동작 또는 검증 증거가 빠짐. 완료로 보고하지 않는다.
- **FAIL:** 핵심 기능이 없거나, 모의 결과·잘못된 검증 표시·범위 누출·회귀가 있음.
- 구현자가 완료했다고 말한 사실이나 테스트의 이름만으로 PASS를 주지 않는다. 실제 실행 결과와 테스트 내용·코드를 확인한다.
- 브라우저 조작은 root가 담당한다. 감사자는 제품 코드 읽기·독립 테스트·HTTP 실험을 수행하고 root의 구체적 브라우저 증거와 합친다.
- 감사와 수정은 반복한다. 마지막 제품 변경 이후 영향을 받는 검사와 필수 빌드가 통과해야 완료다.

## 기능별 세부 판정 경계

### R01 — 표시된 타입과 실제 증명 의존성

- 요구 타입과 제공 타입은 각각 표시한다. 선언문에 쓴 타입과 Lean이 확인한 타입도 혼동하지 않는다.
- 사용 가정은 편집 문맥의 모든 가정을 복사한 목록이 아니라 해당 항에 실제로 필요한 가정이다. 아직 알 수 없으면 미확정이라고 표시한다.
- 서로 다른 두 Watch를 동시에 유지할 수 있어야 한다. 현재 선택을 그대로 두 번 렌더링하는 것은 비교 기능이 아니다.
- 검증 이후 편집한 노드를 이전 타입/항으로 확정 표시하면 FAIL이다.

### R02 — 소스 편집기와 구별되는 실제 노드

- 기존 `.lean` 파일 편집기가 있다는 이유로 LeanScript 노드를 완료했다고 판정하지 않는다.
- 입력 포트에 연결된 값이 본문의 명시적 매개변수가 되어야 하며 출력이 후속 증명에 실제로 쓰여야 한다.
- 임의 수학을 전부 자동 그래프로 바꾸는 것은 이 요구사항이 아니다. 사용자가 명시한 Lean 본문을 가진 컴포넌트를 정직하게 검사하는 것이 범위다.
- 실제 Lean 오류, `sorryAx`, 공리 정책의 거부를 구별한다. 미리 작성한 성공 JSON·성공 문자열은 증거가 아니다.
- 임의 Lean 본문이 들어가는 새 경로는 `source_check.py`의 별도 커널 검사와 공리 감사에 연결한다. 기존 제한 그래프에서 쓰던 stdout 성공 문구만으로 승인하지 않는다.

### R03 — 환경의 선언을 참조하기

- 사용자 입력 이름을 보여 주거나 고정 샘플 목록만 제공하는 것은 선언 조회가 아니다.
- 실제 선언의 완전한 이름, 소속 프로젝트/모듈과 시그니처를 확인한다. 암묵 인자/의존 인자가 있으면 정해진 처리 방식이 보인다.
- 적어도 기본 Lean 선언 하나와 준비된 mathlib 선언 하나가 데이터 경로 전체를 통과해야 한다.
- 종속 포트 및 호출 결과가 조회한 환경과 일치해야 한다. 환경 변경 이후 예전 시그니처를 조용히 유지하지 않는다.

### R04 — 실제 분기와 위치

- 소스의 줄 또는 `case` 문자열을 단순 검색해 만든 트리는 실제 목표 트리의 대체물이 아니다.
- 현재 Lean 버전의 목표·지역 가정을 기반으로 분기를 구분하며, 완성된 목표와 남은 목표를 혼동하지 않는다.
- 깊은 편집 기능은 R05에서 다루지만 읽기 전용 트리도 경로와 실제 위치 탐색까지 동작해야 한다.
- 빈 목표 배열은 해당 위치에 열린 목표가 없다는 관찰이며 전체 정리의 검증 성공이 아니다. Lean 목표/지역 변수 식별자는 세션·문서 버전에 묶고 수정·복원 뒤 재사용하지 않는다.

### R05 — 모든 분기를 닫는 합류

- Boolean 선택기처럼 한 갈래를 골라 최종 결과로 내보내는 것은 일반적인 경우 나누기 증명이 아니다.
- 각 분기의 가정과 결론을 별도로 검사한다. 공통 부모 문맥만 공유하며 형제 문맥의 가정을 사용할 수 없다.
- 결정 가능성/고전 논리 등이 필요한 구현이라면 생성된 증명과 공리 결과에서 그 사실을 드러낸다.

### R06 — 제스처와 의미 안내

- 클릭 두 번 연결은 보조 입력 방식으로 유지해도 되지만 드래그 연결을 대신하지 않는다.
- 타입이 아직 확인되지 않은 포트는 호환으로 확정 표시하지 않는다. 호환 강조는 kernel verification 표시가 아니다.
- 그룹 프록시 포트는 원래 포트에 연결하고, 배치 좌표는 화면 확대·이동 상태를 반영한다.

### R07 — 비용 분리와 버전 일관성

- 가벼운 미리보기 성공 상태와 실제 커널 검증 완료 상태를 구분한다.
- 검증할 문서/모듈/선언/입력 값이 바뀌면 이전 요청의 응답은 새 문서를 검증하지 못한다.
- 자동 모드에는 연속 입력으로 중복 검사를 계속 쌓지 않는 실행 제어가 필요하다. 특정 지연 시간은 요구하지 않는다.
- 수동·자동 모드 전환과 취소가 실제 작업 제어에 연결되어야 한다. 버튼 라벨만 바뀌면 FAIL이다.

### R08 — 변경 가능한 시그니처와 의존 타입

- 현재 읽기 전용 시그니처 카드·고정 출력은 완료 기준이 아니다.
- 예를 들어 앞선 `n : Nat`에 의존하는 `h : n = 0` 같은 입력의 요구 타입을 갱신하는 실험을 포함한다.
- 더 직접적인 값 의존 사례인 `Fin n`도 확인한다. `n`이 바뀌면 이전에 유효했던 항·포트가 새 인덱스 범위에서도 유효한지 다시 검사한다.
- 삭제·타입 변경으로 호환되지 않게 된 와이어를 보이지 않게 유효 처리하지 않는다. 명확한 마이그레이션이나 진단이 있어야 한다.
- 호출 수를 표시하는 것과 **이번 변경에 영향받은 호출을 식별하는 것**을 구별한다.

### R09 — 값·성질·존재 증인의 범위

- `And`의 기존 두 사영만으로 구조체/Subtype/Exists 전체 지원을 대신하지 않는다.
- 구조체 필드는 이름과 실제 타입이 대응해야 한다. 명명된 여러 출력이 서로 다른 실제 값을 가리켜야 한다.
- Subtype의 성질은 해당 값에 대한 증거여야 한다. Exists 분해에서 얻은 증인과 증거는 Lean이 허용하는 제거 범위 안에 둔다.
- 표에서 값을 꺼내거나 소스 주석만 만드는 것이 아니라 해당 출력을 다른 연산/증명에 사용해 검사한다.
- 값의 곱/의존 곱과 증명의 논리곱을 구분한다. 일반 값의 다중 출력을 무조건 `And`로 묶으면 FAIL이다.

### R10 — 문서 버전을 가진 탐색 기록

- 북마크는 단순 노드 좌표 저장이 아니다. 부분 그래프/소스/설명/전후 목표가 대응한다.
- 과거 목표는 스냅샷으로 표시할 수 있으나 현재 목표인 것처럼 갱신 없이 보여 주지 않는다.
- 이전 단계로 탐색하는 것과 undo로 문서를 되돌리는 것은 구분한다. 어느 동작을 하는지 사용자에게 분명해야 한다.

### R11 — 선택 기준의 의존 범위

- 이미 있는 ‘최종 목표만 검사’는 선택한 중간 노드의 의존 범위 미리보기와 다르다.
- 화면의 나머지 노드를 숨기거나 흐리게 하는 방식은 모두 가능하다. 의존 입력과 연결이 빠져서는 안 된다.
- 이 기능은 표시 상태다. 표시에서 제외된 노드를 삭제하거나 가정·소스를 바꾸면 FAIL이다.

### R12 — 명시적인 일괄 의미

- Map/Zip/Product를 선택한 사실과 적용 전·후 개수를 확인할 수 있어야 한다.
- Zip 길이가 다를 때 오류 또는 명시적으로 선택한 정책이 필요하다. 숨은 마지막 항 반복이나 잘라내기는 허용하지 않는다.
- 항목별 원본 식별자를 정렬·복제 후에도 유지한다. 일괄 작업의 한 실패를 정확한 항목에 표시한다.
- 유한 개수의 계산/검사를 전칭명제의 증명으로 표시하지 않는다. 커널은 생성한 실제 주장만 검증한다.

### R13 — 문자열 나열이 아닌 증명 연쇄

- 단계의 좌우 수식과 관계, 이를 잇는 근거가 실제 Lean 증명으로 이어진다.
- 등식과 부등식에 각각 적절한 전이를 사용한다. 마지막 줄만 따로 검사하거나 모든 칸을 성공 처리하면 FAIL이다.
- 편집으로 단계 사이 수식이 달라졌을 때 연쇄 전체가 여전히 맞는지 다시 검사한다.

### R14 — 비교 자료와 신뢰 경계

- 단일 자동 저장본이나 undo 이력만으로 이름 있는 A/B 문서 비교를 대신하지 않는다.
- 각 상태의 본문·대상·환경·정책·검사 결과 출처를 비교/복원할 수 있어야 한다.
- 보존할 환경 식별에는 가능한 실제 Lean 버전 및 준비된 mathlib 기준 식별을 포함한다. 모르는 값은 추정하지 않는다.
- 파일/저장소의 `verified`, `kernelAccepted`, 녹색 상태는 사용자 입력이다. 새로운 실제 검사 없이 검증 사실로 승격하지 않는다.
- 같은 실행 세션에서 이미 검사한 동일 의미·동일 환경의 메모리 캐시와 외부 저장본을 구분한다.

### R15 — 정확한 값 입력

- 자연수 값은 증명에서 사용하는 실제 값이며 슬라이더 장식이나 예제 이름 변경이 아니다.
- 지원 범위를 제한한다면 명시하고, 입력값을 조용히 반올림·잘라내지 않는다. 안전한 정수 범위 밖 값을 부정확한 JavaScript Number로 전달하지 않는다.
- 입력 음성 대조에 `9007199254740993`과 `9007199254740992`를 포함한다. 지원한다면 Lean까지 서로 다른 정확한 값으로 전달하고, 지원하지 않는다면 분명히 거부한다. 두 값을 같게 만드는 변환은 FAIL이다.
- 값에 의존하는 포트/목표/소스와 검증 상태가 함께 갱신된다.

## 모든 기능에 적용하는 회귀 기준

다음은 새 요구사항을 추가하는 것이 아니라 기존 제품 기능의 보존 조건이다.

1. 버전 1·2 그래프 열기, 함수 추출/재사용/내부 편집, 그룹 접기/펼치기·이동·저장.
2. 패널 도킹·분리·크기 변경·순서 변경과 그래프 전체화면/복원.
3. 연결·삭제·속성·이동의 undo/redo, 자동 저장·복구, 저장 실패 안내.
4. 배치·보기만 바뀌면 의미 검증을 유지하고, 논리·환경·정책·입력 값이 바뀌면 무효화.
5. 실제 `.lean` 열기/편집/저장, 오류 위치 이동, 현재 목표·지역 문맥 조회.
6. 고정 mathlib π 원본의 실제 검사 통과, 잘못된 마지막 단계의 타입 오류, `sorryAx` 미완성·사용자 공리 거부·표준 공리 정책 구분.
7. 저장·복원 뒤 새 포트/노드/의존 관계/시그니처/스냅샷이 손실되지 않으며, 저장된 검사 성공을 그대로 신뢰하지 않음.
8. 기존 문서 크기·순환·알 수 없는 참조 검사와 새로운 범위/타입 안전성 유지.

## 증거 기록 형식

감사 회차마다 `AUDIT-<회차>.md` 또는 같은 디렉터리의 구조화된 결과에 다음을 기록한다.

- 검사한 파일 또는 커밋/작업 트리 시점과 요구사항 ID.
- 실제 실행한 명령, 종료 코드, 핵심 결과, 원본 로그 경로.

- root가 확인한 브라우저 행동과 파일/이미지 증거. 검사하지 않은 UI는 ‘미확인’으로 남긴다.

## 초기 코드 점검 근거

초기 점검은 새 구현 전의 소스 읽기 결과이며, 이 문서에서 기존 전체 테스트를 실행했다고 주장하지 않는다.

- `web/model.mjs`: 기존 종류는 assumption/apply/pair/left/right/goal/module/group이며 목록·case·Nat·LeanScript 데이터 모델은 없다.
- `web/app.js::nodeType/renderGraph`: 출력 타입과 단순 툴팁이 있음. 두 고정 Watch·사용 가정·입력 요구 타입 Inspector는 없다.
- `web/app.js::renderWires/inputClicked`: 와이어는 SVG 곡선이며 연결은 클릭 방식이다. 타입/출처 조회와 호환 포트 강조는 없다.
- `web/app.js::renderLibrary`, `MODULES.md`: 시그니처 카드와 호출 수, 내부 편집은 있으나 입력/출력 선언은 고정이다.
- `web/app.js::checkGraph`, `web/lean-editor.mjs`: 수동 검사와 소스 문맥 지연 조회, 버전 무효화는 있으나 Data Dam 수동/자동 설정은 없다.
- `web/lean-editor.mjs::readContext`: 실제 Lean 문맥을 텍스트로 표시한다. 목표 경로·분기 트리·북마크는 없다.
- `graph_scope.py`: 최종 목표의 의존 노드 검사 기능은 있다. 임의 선택 노드의 화면 미리보기는 없다.
- `web/history.mjs`, `web/draft.mjs`, `web/document.mjs`: 한 문서의 이력·자동 복구와 그래프/Lean 문서 저장이 있다. 이름 있는 A/B 컬렉션은 없다.
- `source_check.py`, `lean_policy.py`: 실제 소스 컴파일·별도 커널 검사·공리 정책 경로가 있다. 새 노드도 이 신뢰 경계를 지켜야 한다.

현재 모든 ID는 새 구현과 독립 실험을 기다리는 상태다. 초기 PARTIAL은 기존 기반 기능이 일부 있다는 뜻이며 새 요구사항 완료를 뜻하지 않는다.
