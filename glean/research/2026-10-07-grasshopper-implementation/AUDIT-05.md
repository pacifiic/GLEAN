# 선언 참조·북마크·문서 비교와 최종 UI 수락 감사

Copyright (c) 2026 GLEAN contributors. Released under Apache 2.0.

사용자가 실행 예산을 보충한 뒤 이전 감사의 고정된 15개 요구사항을 계속 확인한다.
이 기록은 현재 작업 중인 코드에 대한 점진적 감사이며, 최종 전체 빌드·검사 통과를
아직 주장하지 않는다. 제품 코드는 수정하지 않고, 독립 입력·모델/이벤트 실험과
root의 실제 CUA 브라우저 관찰을 합친다.

## R05 — 실제 분기 편집과 오류 위치 이동 수락

root가 AUDIT-03의 `or_cases` fixture를 실제 브라우저로 가져와 확인했다.

- 오른쪽 분기를 열면 범위는 `root/case/right`이며 지역 증거는 `hq : Q`이다.
  형제 분기의 `hp`는 이 범위의 선택 가능한 지역 입력에 없다.
- 오른쪽 join 본문을 `Or.inl hq`에서 `Or.inr hq`로 바꾸고 실제 Lean 검사를 실행하면
  Q 항에 P 타입을 요구하는 오류가 L32에 발생한다.
- 루트로 돌아간 뒤 진단 L32를 누르면 `root/case/right`를 다시 열고 join 노드를 선택한다.
- 본문을 `Or.inl hq`로 복구하고 새로고침한 뒤 같은 분기에 들어가면 복구한 본문이
  유지되고 검증 상태는 미검증이다.

앞선 독립 실제 커널의 양쪽 분기 통과, 필수 분기 누락·틀린 분기·형제 가정 참조 거부와
합쳐 R05를 PASS로 판정한다. 증거를 임의 Lean 코드의 자동 그래프 변환으로 확대하지 않는다.

## R15 — 정확한 Nat 편집·복구 수락

AUDIT-04의 실제 검사에서 0/7/`9007199254740993`은 통과하고, 큰 값만
`9007199254740992`로 바꿔 기존 목표를 유지한 대조는 거부됐다. 또한 n=3에서 유효한
Fin 3 증명을 n=2의 호출로 바꾸면 두 공유 호출이 각각 거부됐다.

root가 실제 브라우저로 추가 확인한 내용:

- `9007199254740993`의 슬라이더에서 ArrowRight를 누르면 정확히 `9007199254740994`가 된다.
- 값 변경 즉시 ‘타입 그래프 변경됨’ 상태로 검증을 해제한다.
- Undo는 `9007199254740993`, Redo 후 새로고침은 `9007199254740994`를 복구하며 새 검사를 요구한다.
- 입력 `-1`과 `1.5`에서 검증을 누르면 정규 십진 자연수 형식 오류로 거부한다.

실제 수학 대조와 사용자 접근 경로·복구 근거를 합쳐 R15를 PASS로 판정한다.

## R09 — 이름 있는 출력의 연결과 복구 수락

root가 실제 Subtype fixture의 `value`(val)와 `nonnegative`(property)가 서로 다른 출력
포트로 표시되는 것을 확인했다. 후속 use 노드에는 `k : Nat ← make.value`와
`hk : 0 ≤ k ← make.nonnegative`가 각각 연결됐다. hk를 선택 메뉴로 끊은 뒤
nonnegative 출력 클릭→hk 입력 클릭으로 재연결하고, 새로고침해도 두 이름 있는 연결과
속성을 유지했다.

Agent 3은 출력 삭제가 보이는 DOM만 바꾸던 결함을 발견했다. 구현자 수정 뒤 동일 이벤트
재현에서 삭제한 출력이 저장 문서에서도 제거되고 onChange 1회·기존 검사 결과 null을
확인했다. 원본 재검사 자료는 [design-audit-lifecycle-retest.json](design-audit-lifecycle-retest.json)이다.

앞선 실제 Prod의 서로 다른 필드, Subtype 값/성질의 종속 사용, Exists 분기 내 증인/증거
재조립 통과 및 틀린 필드/성질·존재 증인 범위 이탈 거부와 합쳐 R09를 PASS로 판정한다.

## R13 — 편집·오류 위치·복구 중간 수락

root가 실제 부등식 Calc fixture의 첫 중간 항을 `x + 1`에서 `x + 3`으로 바꿨다.
‘적용’ 전 즉시 문서에 반영되고 실제 Lean은 첫 단계 근거 `Nat.le_succ x`의 타입 불일치와
후속 `x + 3 ≤ x + 2` 오류를 L30/L31에 각각 보고했다. 문서 속성 화면으로 이동한 뒤
L30 진단을 누르면 Calc 컴포넌트 속성이 다시 열린다. `x + 1`을 복구하고 새로고침하면
값이 보존되고 미검증이다.

현재 오류 이동이 해당 Calc 컴포넌트까지는 도달하지만 해당 first/second 단계 행을
직접 표시하지 않았다. ‘원인 단계 이동’ 기준을 충족하도록 source key의 마지막 step ID로
해당 행을 강조·이동하도록 구현자에게 요청했다. 이 수정과 재검사 전에는 R13 PARTIAL이다.

## DREQ-01 — 실제 선언의 hygienic 바인더를 포트 별칭으로 사용함

독립 [audit_declarations.py](audit_declarations.py)는 실제 Lean Meta API를 통해 다음 두 선언을
조회하고 제품 GraphCheckService의 별도 예상 타입 검사·커널 재검사 경로에 넣었다.

- `Nat.add_zero`: 입력 `n : Nat`, 출력 `n + 0 = n`, 실제 커널 통과.
- `Nat.le_trans`: 암묵 입력 `n,m,k : Nat` 뒤 두 증명 입력의 표시 이름이 모두
  `a._@._internal._hyg.0`이다. 이를 그대로 입력 별칭으로 쓰면 그래프 컴파일러가
  `Input aliases must be unique non-keyword ASCII Lean names`로 거부한다.

두 번째 선언은 정상 Lean 선언이며 암묵/의존 입력 지원 요구사항의 실제 사례다.
조회한 telescope의 지역 변수에 안전하고 고유한 별칭을 부여하고 그 문맥에서 타입/결과를
pretty-print하도록 구현자에게 요청했다. 의존 타입 문자열을 추측해서 대체하는 방식은
안전한 해결 근거가 아니다. 원본 입력·결과는 [declaration-results.json](declaration-results.json)에 보존한다.

## 진행 중인 독립 검사와 회귀

- 실제 mathlib `Real.pi_pos` 참조와, 프로젝트 Lean 입력 파일을 추가하여 실제 환경 식별자를
  바꾼 뒤 이전 시그니처 거부/새 조회 승인 대조를 실행 중이다. 실제 π 전체 LSP 검사와 중복하지 않는다.
- Agent 3이 실제 typed 편집 이벤트로 출력/Calc 삭제, 문서 교체 뒤 임시 와이어,
  malformed A/B 출처, 늦은 미리보기·선언 오류 회귀를 찾아 구현자에게 전달했다.
  이 감사자는 수정 통보만으로 해당 요구사항을 PASS로 바꾸지 않는다.
