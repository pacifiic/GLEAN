## 변경 전 관찰

- 대상: `http://127.0.0.1:8765/`, IAB viewport 735×625, 기존 Port compatibility audit v3 문서.
- [변경 전 화면](/Users/moonone/GLEAN/glean/research/2026-10-07-block-hierarchy-implementation/ui-before.jpg).
- **UI-01 / 가독성:** 노드 원래 너비 190px이 화면에서 약 96px. 배율 약 50.5%, 12px 글자의 실효 크기가 약 6px다. 선택·진단 시 읽을 수 있는 배율, 100% 복귀와 현재 배율 표시가 필요하다.
- **UI-02 / 도구 밀도:** typed-toolbar가 80px이며 루트/경로/도구가 3행을 차지한다. 새 숨김·격리·중첩 도구를 같은 줄 나열로 계속 추가하면 캔버스가 좁아진다. 유형별 추가 메뉴와 보기 메뉴로 정리해야 한다.
- **UI-03 / 이름:** 카드 제목에 input/script가 반복되고 내부 ID가 그대로 작은 글씨로 보인다. 사용자 이름·역할을 먼저 읽을 수 있어야 한다. 내부 ID는 Inspector에 둘 수 있다.
- **UI-04 / 편집 진입:** 도킹 패널이 접힌 상태에서 script 카드를 선택해도 편집 진입점이 나타나지 않는다. 명시적인 `코드 열기 / 내부 열기`와 캔버스 복귀가 필요하다.
- **UI-05 / 진행 표시:** 시험 JSON을 열어 증명 확인 패널이 열린 상태에서 `Lean으로 검증`을 누르면 해당 패널이 닫혔다. DOM 상태는 `Lean 타입·커널 검사 중`이지만 화면에서는 보이지 않았다. 명시적 검증·편집 요청은 패널을 토글하지 않고 열어야 한다.
- **UI-06 / 타입 가독성:** 실제 호출 A의 와이어 타입이 `Eq (instHAdd.hAdd glean_component_5 0) glean_component_5`로 보인다. 사용자 문맥의 Lean 표기와 내부 상세 정보를 나눠야 한다. 표시를 위한 문자열 치환으로 타입의 의미를 왜곡해서는 안 된다.

## 긍정 대조 fixture

[ui-mixed-3-level.json](/Users/moonone/GLEAN/glean/research/2026-10-07-block-hierarchy-implementation/ui-mixed-3-level.json)은 3단 그래프 정의 안에 코드 블록을 두고 같은 큰 정의를 `n=3`, `n=5`로 두 번 호출한다. 두 결과를 And로 합치는 실제 Lean 증명이다.

생성 소스의 Lean 컴파일 exit 0을 확인했다. 기존 UI에서 파일 선택기로 이 JSON을 열고 `Lean으로 검증`을 실행했으며, `수학 그래프 검증 완료 / 커널 재검사 + 의도한 목표 타입 대조 · 공리: 없음`을 확인했다. 이는 새 숨김·격리 기능의 완료 증거가 아니라 이후 동작 비교에 사용할 올바른 증명 대조군이다.

## 실제 화면 검사 기준

1. 기본 창과 그래프 전체화면에서 숨김/격리 진입·상태·종료가 보이는가.
2. 선택하지 않았을 때와 여러 개 선택했을 때 명령의 활성 상태와 설명이 맞는가.
3. 선택만 보기 이후 다른 블록을 클릭해도 대상이 바뀌지 않는가.
4. 숨긴 항목 찾기, 대상 추가, 다시 Hide, 격리 종료가 예상대로 동작하는가.
5. 3단 중첩의 경로와 돌아가기, 일반 정의와 호출 문맥을 구분할 수 있는가.
6. 긴 코드 편집·확대·오류 행 이동·복귀가 가능한가.
7. Lean 파일을 열자마자 원문을 볼 수 있고 분석 중/미확정/검증 상태가 명확한가.
8. 연결 경계·오류 요약이 남고 가짜 직결 와이어가 생기지 않는가.
9. 글자가 잘리거나 도구가 겹치지 않고, 작은 창과 넓은 창에서 핵심 동작을 찾을 수 있는가.
10. Grasshopper 스타일의 색·캡슐·소켓·선택 강조가 일관되고 내부 구현 용어가 주 동선을 압도하지 않는가.

- **UI-08 / Shift 선택:** callA 제목 클릭 → join 제목 Shift+클릭 → 보기 메뉴에서 선택 숨기기/선택만 보기 모두 비활성. title pointerdown에서 선택을 한 개로 만든 뒤 click에서 같은 ID를 해제했다. 카드 본문으로 Shift 선택하면 다음 동작을 시험할 수 있었다. 구현자에게 우선 수정 요청했다.
- 패널을 접고 전체화면에 들어간 뒤 callA+join의 카드 본문을 Shift 선택해 `선택만 보기`를 실행했다. `격리 1단계 / 대상 2 / 격리 숨김 3 / 수동 숨김 0`과 종료 버튼을 확인했다. [첫 격리 화면](/Users/moonone/GLEAN/glean/research/2026-10-07-block-hierarchy-implementation/ui-first-isolation.jpg).
- **UI-09 / 격리 시각 밀도:** 숨긴 three/callB/five가 모두 폭 190px 녹색 경계 캡슐로 남으며, 양 끝이 숨겨진 five→callB 연결도 표시된다. 대규모 그래프에서는 집중 효과가 줄어든다. 화면에는 선택 영역에 접한 작은 중립색 경계만 남기고, 실제 전체 간선/노드는 데이터·검사에 유지하도록 요청했다. 보기 메뉴도 동작 실행 뒤 열려 있어 추가 닫기가 필요했다.
- **UI-10 / 진입점:** 계획의 카드 우클릭 경로를 제품 이벤트에서 아직 찾지 못해 구현 확인을 요청했다. 현재 확인한 진입점은 상단 보기 메뉴다. 실제 우클릭 동작은 다음 배치에서 시험한다.

### 두 번째 UI 배치: 실제 재검사

- UI-08 제목 Shift 다중 선택과 UI-10 선택된 카드 우클릭의 선택 보존을 실제 브라우저에서 확인했다. callA+join을 선택해 우클릭 메뉴로 격리했고 실행 뒤 메뉴가 닫혔다.
- UI-09 수정 확인: 실제 카드 2개, 직접 경계 2개(94px 중립색), 원래 endpoint를 보존하는 선 3개가 표시됐다. 양 끝이 숨겨진 five→callB 선은 화면에서 생략됐다. [정리된 격리 화면](ui-isolation-refined.jpg).
- UI-07은 아직 부분 수정이다. 오른쪽 패널이 열려 있을 때 전체화면 버튼의 중앙 hit target은 올바르지만, 첫 click은 패널만 접으며 전체화면은 false에 남았다. 위치가 바뀐 버튼을 다시 클릭하면 전체화면에 들어갔다. 구현자에게 pointerdown 중 도크 레이아웃 변경 가능성과 함께 전달했다.
- callA 내부에서 n_in을 수동 숨긴 뒤 상위로 돌아왔을 때 부모 격리는 유지됐다. 격리를 종료하고 callB 내부를 열면 n_in이 보이고 숨김 0개였다. 공유 정의의 호출별 표시 상태가 분리되는 실제 경로를 확인했다.
- callB→outer→middle→leaf의 3단 내부 탐색과 코드 열기가 동작했다. [중첩 코드 편집기 첫 화면](ui-nested-code-first.jpg).
- leaf 코드를 `by / exact True.intro`로 수정하고 캔버스로 돌아가 실제 Lean 검사를 실행했다. `True`와 `n + 0 = n`의 타입 불일치로 거부됐다. 오류 블록을 숨긴 뒤에도 전역 오류 상태가 유지됐다. 진단 L29를 클릭하면 숨긴 proof가 100% 배율로 임시 공개되고 이전 보기 복귀 경로가 나타났다. 아직 코드 편집기와 정확한 본문 행으로 이동하지 않아 B03 완료 근거는 아니다.
- **UI-11 / 코드 버튼 겹침:** 두 입력 pa/pb가 있는 join 카드에서 코드 열기 버튼이 두 번째 pb 포트와 겹친다. 입력 개수를 반영한 카드 높이와 별도 footer가 필요하다.
- **UI-12 / 호출 경로:** 경로가 `module/outer · 호출별 보기`만 보여 A/B를 구별할 수 없다. 실제 호출 이름의 경로와 공유 정의 편집의 영향 범위를 표시해야 한다.
- **UI-13 / 전체화면 오류 진입:** 전역 오류 텍스트와 tooltip은 보이지만 클릭해 진단을 열 수 없어, 전체화면을 나가고 도킹 패널을 찾아야 한다. 그래프 안에서 진단·코드 행으로 이동할 수 있는 진입점이 필요하다. 수동 숨김만 했을 때 임시 진단 표시 종료가 `격리로 돌아가기`라고 나오는 문구도 고쳐야 한다.

위 관찰은 native UI와 실제 Lean 결과를 구별해 기록했다. 호출별 인자의 타입 대입, 긴 본문, 복구 등 남은 수락 조건을 대신하지 않는다.

### 저장·이력·직접 작성 추가 확인

- UI-07 최신 수정은 통과: 오른쪽 도크를 연 채 전체화면을 한 번 클릭하면 진입한다. UI-11도 통과: join의 pb 포트는 y394–405.5, 코드 버튼은 y427–447에 있어 겹치지 않는다.
- UI-12는 호출 이름 경로와 공유 정의 편집의 영향 설명이 나타났다. 실제 연결 인자 표시의 독립 감사는 Agent 2가 계속한다.
- 수동 five 숨김→callA+join 격리→같은 선택 반복→join만 두 번째 격리→이전 격리→join 숨김→종료: five와 join의 수동 숨김이 유지됐다. Cmd+Z는 join 숨김을 취소했고 격리 동작은 Undo를 소비하지 않았다.
- 활성 격리 안에서도 join Hide→Cmd+Z는 join을 다시 표시하고 격리 1단계/대상 2를 유지했다. 새로고침 후 자동으로 격리되지 않고 `이전 격리 복원` 버튼이 나타나며, 클릭하면 정확히 callA+join이 복원됐다. 자식 범위의 탐색 경로 복원은 별도 감사 중이다.
- 숨긴 목록에서 수동 숨긴 five 검색→대상 추가로 표시→five를 다시 Hide하면 최신 Hide가 적용됐다. 열린 목록에서 Escape는 목록만 닫고 전체화면을 유지했다.
- 손상된 v3 표현 fixture를 파일 선택기로 열었다. 지속적인 노란 복구 경고, 미검증 상태, 원본 5개 노드와 4개 선을 확인했다. 원본 표현 저장의 실제 다운로드를 원래 presentation 객체와 비교한 결과 완전히 같았다. [복구 화면](ui-presentation-recovery.jpg), [실제 보관된 원본](ui-presentation-original.json).
- **UI-14 / 화면 복귀:** 오른쪽 도크가 열린 좁은 캔버스에서 진단 이동한 뒤 전체화면 전환·임시 표시 복귀 시 입력 카드가 x=-199에 남았다. 선택 없는 `선택 맞춤`도 무동작이다. 이전 viewport 복원과 전체 맞춤 진입점이 필요하다.
- **UI-15 / 생성 위치:** 새 부모 호출이 공개 입력 위에 생긴다. public_x x90/y249와 새 call x120/y259(모두 폭190)가 겹쳐 공개 출력 포트를 누를 수 없었다. 별도 빈 공간 배치가 필요하다. 시험은 카드를 빈 공간으로 끌어 옮겨 계속했다.
- **UI-16 / 비동기 메뉴:** 새 부모 생성 직후 더보기 메뉴를 열면 타입 미리보기 응답이 도구 모음을 다시 만들면서 메뉴를 닫았다. 미검증/오류 상태 갱신이 현재 메뉴와 키보드 포커스를 보존해야 한다.

### 직접 만든 혼합 계층의 실제 검증

기존 정상 증명에 UI 메뉴로 4개 정의를 직접 추가했다. 새 graph 부모에는 code 자식과 graph 자식을 넣었고, graph 자식에는 code 손자를 넣었다. 손자의 본문은 직접 `x + 0`으로 바꿨다. 각 공개 입력→자식 호출→내부 결과를 화면의 출력/입력 소켓 클릭으로 연결했다. 루트에서는 Nat 3과 기존 callA 사이에 새 graph 부모를 삽입했다.

- 새 정의: `module_7c6de242`(graph 부모, 4노드), `module_4b8dc041`(code 자식, 2노드), `module_66c92602`(graph 자식, 3노드), `module_1f869b6d`(code 손자, 2노드).
- 새 루트 호출: `call_bed2a112`. three→새 호출→callA 연결을 실제로 교체했다.
- 브라우저의 전체 검사 결과: **커널 재검사 + 의도한 목표 타입 대조 · 공리 없음**. 부모/자식이 단순 시각 그룹이 아니라 생성 증명의 의미 경로에 포함됐다.
- [실제 내보낸 문서](ui-authored-mixed.glean.json) 15,098bytes, 7개 정의. SHA256 `3cdfe450c394163020fcb53931e9622a6c5ec84c1cf8bd493b071a70f0fe77a2`.

### 실제 선언 분석의 첫 UI 배치

581바이트의 namespace/private/macro/instance/중간 오류 fixture를 파일 선택기로 가져와 분석했다. 실제 Lean이 확인한 12개 선언과 `파일 오류 있음 · 증명 검증과 별도` 상태가 나타났다. `Scoped.from_hidden`의 `n : Nat → Scoped.hidden n = n + 1` 계약과 직접 의존 목록이 맞았다. 현재 파일 private 의존을 클릭하면 그 선언으로 좁혀지고, 원문 위치는 실제 10행으로 이동했다.

**UI-24:** 분석 후 파일 부제에 `분석 전`이 남고, 원본/환경 SHA 전체가 한 줄을 차지해 검색창을 밀며, `Lean.ConstantKind.thm` 같은 내부 문자열이 표시됐다. 분석 정보는 접는 상세로 옮기고 종류/상태를 사용자 용어로 표시하도록 요청했다. 이는 최초 동작 확인이며 P1 전체 수락을 대신하지 않는다.

- 1,000개 선언 파일의 실제 분석 후 DOM에는 처음 50개 카드와 `더 보기 (50/1000)`가 나타났다. 마지막 `declaration_0999` 검색은 도구/AX 포함 114ms였고 L1008/`n : Nat → n + 0 = n`/직접 의존 `Nat.add_zero`가 맞았다.
- `Nat.add_zero · 설치 환경` 조회 → 별도 출처 설명 → 참조 그래프 생성 → 실제 Lean 검사 전체 흐름을 수행했다. 커널/의도한 목표 검사와 공리 없음이 확인됐다. [실제 참조 문서](ui-installed-reference.glean.json)는 `Init.Core` import, 공개 n 입력, reference 노드와 실제 와이어 1개를 포함한다. [검증 화면](ui-installed-reference-verified.jpg).

### 200개 공유 호출과 자식 탐색 복구

- 1MiB 정의를 200번 사용하는 파일을 실제 가져온 시간은 도구/AX 포함 836ms였다. call0만 격리(747ms)하면 실제 호출과 직접 입력 경계 2개 카드만 남았다. call0도 숨겨 완전히 빈 화면이 되어도 `격리 종료`와 `숨긴 항목 201개` 접근 경로는 유지됐다. Cmd+Z는 수동 숨김만 취소하고 격리는 보존했다.
- call0 내부 본문에 주석 14자를 입력한 뒤 캔버스로 돌아와 문서 Undo를 실행했다. 실제 검사 시작→취소 뒤 `검사 취소됨 · 문서는 보관됩니다` 상태를 확인했다. [취소 후 다운로드](ui-shared-200-after-cancel.glean.json)는 200회 호출/정의 1개/본문 1개, 1,048,483자의 원문 SHA256 `8b8ad61bdda3b1f598f3dab08f7adfa11246133f7ed0838f52798f7bc2426eab`와 일치한다. 이 시험은 200회 호출의 검증 성공을 주장하지 않는다.
- root에서 callA 격리→A 내부 nested 격리→새로고침 시 루트 전체가 보이고 `이전 격리 복원`이 나타났다. 명시적 복원은 A의 자식 격리/선택을 되살렸고, 상위로 돌아가면 루트 callA 격리가 복구됐다. 루트 격리를 종료한 후 B 내부는 숨김 0개이며 인자 `five.out = 5`가 표시됐다(A는 `three.out = 3`).
- B 내부 입력 Hide→한 단계 내부 탐색→Cmd+Z는 현재 탐색 경로를 바꾸지 않고 숨김 편집을 취소했다. 부모로 돌아오면 입력이 표시되고 복귀 선택은 nested였다. 미완성 연결의 Esc는 격리와 전체화면을 보존했으며, `격리 종료` 버튼에서 Enter로 종료할 수 있었다. 후보 tooltip 잔류는 독립 감사 E05로 수정 요청했다.
