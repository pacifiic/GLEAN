# GLEAN typed graph v3 contract

Copyright (c) 2026 GLEAN contributors. Released under Apache 2.0.

Version 1/2 remain the restricted propositional graph format. Version 3 is an explicit Lean component graph, not an automatic conversion of arbitrary source.

A root has `version:3`, `name`, `projectId` (`glean`/`mathlib`), `imports` (bounded Lean module names), `policy`, `inputs:[{id,name,type}]`, `goal`, `nodes`, `edges`, `result:{node,output}`, `modules`, and optional legacy presentation `groups`. Every graph body has local node/edge IDs. A module has stable `id`, display `name`, optional `blockKind:"code"|"graph"`, `inputs`, `outputType`, `nodes`, `edges`, `result`. Both block kinds use the same semantic graph/public-contract schema; a code block opens its script body directly. Module references must form a DAG. Root input aliases and each component's parameter aliases are unique ASCII Lean identifiers, excluding keywords; generated global names come only from numeric indices. Renames are semantic edits. `autoImplicit false` rejects undeclared binders.

Edges have `id`, `source`, `output`, `target`, `input`. The source and target must both exist in the same graph body. Each target input has at most one source. Each node has a stable `id`, `kind`, `x`, `y`. Outputs are named and have stable IDs. Default output is `out`.

- `input`: `ref` is a declared input ID of the current root/module/case body.
- `nat`: `value` is an exact canonical decimal string. No floating point conversion. Length is bounded.
- `script`: `inputs`, `outputType`, and Lean term `body`. Body sees only its explicit parameter aliases and imported declarations.
- `reference`: qualified `declaration`, actual environment signature queried from Lean; all binders are exposed explicitly (including implicit/typeclass binders). Unsupported unresolved universe signatures are diagnosed. Environment and declaration changes invalidate the signature and checks.
- `module`: `ref` points to a shared module definition. Ports follow that definition's stable input IDs.
- `construct`: same explicit signature/body as script, plus `outputs:[{id,name,type,term}]`. Projection expressions see `value` (the constructed value) and explicit component inputs. Structure and Subtype projections remain actual Lean expressions. `Exists` witnesses require a scoped case body, never unrestricted projections.
- `calc`: explicit `inputs`, `outputType`, `start`, and `steps:[{id,relation,term,proof}]`. Relations are `=`, `≤`, or `<`; the whole generated `calc` is elaborated.
- `cases`: explicit `inputs`, `scrutinee` parameter ID, `outputType`, and `branches:[{id,constructor,binders:[{id,name,type}],nodes,edges,result}]`. Branch input nodes may refer to the case's explicit inputs and that branch's binders. All branch node/edge identities live under `(parent scope, case node ID, branch ID)`. Lean elaborates the exhaustive `match` and checks dependent eliminators and Prop elimination restrictions. Branch results never become outputs except through the case join.

Fragment boundaries are enforced by a trusted Lean term elaborator calling `Parser.runParserCategory env term text`, which requires full input consumption. Fragment text is encoded as Lean string data; it cannot close a generated declaration. Aliases are actual Lean local binder names, not textual substitution. Nested local Lean binders obey Lean's own scoping. Quoted identifiers inside terms remain Lean syntax.

Every final graph check uses cancellable `source_check` elaboration, independent serialized-constant kernel replay, and axiom policy. In addition, the graph's expected root telescope → goal is independently compiled in a separate fresh source module. The auditor compares the replayed target's actual type to that independently obtained expected expression with kernel definitional equality. Graph text and submitted stdout cannot replace the expected signature.

Limits: 256 total nodes, 512 total edges, 32 module definitions, 16 inputs/outputs per component, bounded scope nesting, 1 MiB UTF-8 script bodies, 8 MiB generated source and 24 MiB serialized documents/HTTP requests. Graph expansion and parent creation preflight whole-document limits atomically. Missing input, unknown output, cross-scope reference, cycles, duplicate IDs, and omitted branch results fail before verification. Actual Lean rejects ill-typed dependent calls, nonexhaustive cases, invalid projection fields, unresolved metavariables, and bad calc steps. Source maps connect generated ranges to scope/node/step IDs; fragment diagnostics also carry original body line and Unicode codepoint column. UI navigation converts the column to UTF-16 without altering body bytes. Diagnostic display never determines acceptance.

Map/Zip/Product are explicit bounded graph expansions. They generate concrete module/reference calls with source item IDs and operation provenance. Zip requires equal lengths; Product is the Cartesian product; no implicit broadcast or finite-to-universal proof claim.

The document envelope's `presentation:{version:1,scopes,occurrenceViews}` stores manual Hide and nested visual containers. Each scope has `hidden` entity IDs (`n:node`/`c:container`) and `containers` with a same-scope child forest, collapse state and finite coordinates. Legacy groups migrate into this common view. Canonical occurrence keys include the exact continuous call trail and final semantic scope; shared-definition call A/B views do not reuse each other's manual Hide. Malformed view metadata is quarantined with explicit warnings and exact original recovery, while semantic graph data remains intact.

Runtime isolation contains fixed target sets, explicit temporary additions, diagnostic ancestor reveal and prior viewport. It is excluded from document Undo and ordinary file export. A separate recovery entry is validated against the document/scope/call trail; it is offered for explicit resumption with selection and return navigation. Collapsed and hidden boundary proxy ports use injective structured endpoint identities and preserve original edge IDs/endpoints. Hidden-hidden edges are omitted from rendering, never replaced with bypass wires. Full-document validation and the global final-target result remain visible independently of the current view.

Direct dependency expansion uses same-scope static wires, or explicitly labeled source-analysis constant references in source mode. Only one step is added; manually hidden dependencies require explicit temporary addition. Body-source references not analyzed in the typed graph remain uncertain. Clipboard copy/paste duplicates selected same-document/same-scope blocks and internal edges with new IDs, recursively rebinding Cases-local endpoints while retaining shared module references. Pasting from another scope/document is rejected. New blocks and batch calls join the active isolation target set.

The wide script editor provides line numbers, search, line jumps, folding, precise diagnostic selection and actual Lean cursor goals through the generated context. Closing/query cancellation never truncates the body; stale goal results are suppressed. Undo snapshots share unchanged subtrees, and shared definitions serialize once per definition rather than once per call. The 120-second job deadline and kernel/axiom rules remain in force for long bodies; optional metadata normalization has explicit reduction/owned-let budgets. Arbitrary dependent subgraph extraction and automatic tactic-step conversion are later stages, not implied by direct parent authoring.


Declaration binder aliases are assigned in Lean's actual local context before dependent types are rendered. Hygienic, duplicate, Unicode or keyword names receive safe unique aliases; `originalName` retains attribution. `implicit` and `instance` flags survive editing and persistence. Installed source ranges come from Lean's declaration-range extension, resolved under the fixed project's package/toolchain roots. Unavailable source is reported explicitly.

Successful kernel replay also returns actual binding types, instantiated callsite parameter types and normalized generated-helper dependencies. Cases branches compile to closed helpers, so their local input/output metadata retains scope identity. `typedNodeAudit` audits each generated output helper's actual constant/axiom cone separately from the final target. An unused module's `sorry` cannot inherit a green component badge from a valid final theorem. Before metadata exists, Inspector and candidate connections are explicitly uncertain.
Optional let metadata is keyed by exact compiler owner plus local generated binding name. User lets with similar names cannot replace another scope's port types or used assumptions.

`review.notebook` stores two named document variants and up to twenty proof-step bookmarks. Variants contain detached validated documents plus historical source/environment/audit records; comparing variants exposes graph-field and Lean-line differences. Bookmarks retain the selected subgraph/source range, explanation and separate before/after goal observations bound to project, filename, source identity, session and document version. IDs in stored observations are historical labels, never live Lean RPC references. Source/profile/file changes clear obsolete graph associations. Stored verification flags are never accepted as kernel evidence.

Presentation-only undo may reuse a result already obtained in memory only after querying the current environment and checking matching semantics, check scope and request epoch. File restoration and reload always clear verification. Environment hashing covers actual Lean binary/project/package source/configuration identities and compiled-artifact metadata; it does not claim a complete content attestation of every compiled library.
